# RoCE all-gather for a group of ranks

One-shot all-gather between DGX Sparks over RoCE: the GPU side of b12x's "RoCEnante" exchange (https://github.com/local-inference-lab/b12x, b12x/comm/roce, Apache License 2.0), written for two ranks and generalised to any world whose ranks all reach each other (two on one cable; two, four or more on a switch; at most `roce.max_world` = 8). The host side (zig/src/cuda/roce.zig) owns a pinned region the GPU and the NICs reach:

```
  recv[slot][peer]       each peer's shard, written by that peer's NIC (2 slots of world - 1 of slot_bytes)
  flag[slot][peer][stripe]  the sequence a peer's NIC writes after that stripe (128 bytes apart)
  send[slot]             this rank's shard, staged here for its NICs (2 slots)
  ctrl                   {seq, nbytes of slot 0, nbytes of slot 1, error seq, missing hca, missing rank, probe tokens}
```

A rank's peers are the other ranks in rank order (rank 2's peers 0, 1, 3 are its peer numbers 0, 1, 2); every rank opens one RC queue pair a peer an HCA, and at world 2 (one peer) every offset and every byte is the two-rank design's.

One launch: (1) every block stages its share of the shard into send[seq & 1]; (2) the last block to stage publishes the slot's size and rings ctrl.seq after a system fence, and the proxy thread RDMA-writes the shard to every peer, each copy on this rank's queue pair toward that peer, and then a flag per stripe on the same queue pair (so a flag never lands before its stripe); (3) one thread a (peer, stripe) waits for that stripe's flag, (world - 1) x stripes of them; (4) every block writes every shard into the output slot of its rank (the layout NCCL's all-gather gives); (5) the last block to finish advances the device epoch, so a CUDA graph replays the exchange with new sequences. A wait past the spin limit poisons the exchange: later launches return at once and the host reports the error, naming the stripe and the rank whose flag never came.

## Host side

Small all-gathers between two ranks as one-shot RDMA writes over RoCE: b12x's "RoCEnante" exchange (https://github.com/local-inference-lab/b12x, b12x/comm/roce, Apache License 2.0), written for two ranks: the kernel (kernels/cuda/roce_gather.cu) stages this rank's shard in pinned host memory and rings a doorbell; a proxy thread here RDMA-writes it to the peer, striped over the HCAs, each stripe followed by its sequence flag on the same queue pair; the kernel waits for the peer's flags and copies both shards out. A decode step's gathers are a few rows of partials. On two GB10s with one ConnectX-7 cable (NCCL 2.30.7, `tf-cuda-test roce-gather`, 2,000 calls back to back) this path took 10.4 us a call at 4 KiB a rank against NCCL's 12.3, 11.6 against 13.5 at 8 KiB, 17.4 against 20.5 at 32 KiB, and 17.4 against 51.5 at 64 KiB. libibverbs is opened at run time (as the driver and NCCL are): without it, or without an active HCA, the caller keeps NCCL.

## Setup and use

`tp_group.Group.openRoce` brings the path up on the group: each rank opens its HCAs and a queue pair a peer an HCA, and what each brings (its region, keys, queue pairs and the largest shard it would send) crosses the group's own NCCL communicator (an all-gather), as does each rank's verdict after connecting. Every rank gets the path or none does. Two ranks ask for it unless `TF_ROCE=0`; three or more ask only with `TF_ROCE=1` on every rank (the GLM start refuses ranks that differ), which also splits the DFlash2 drafter's MLP across them. MiniMax-M3 asks for the gather at two ranks only. Without it a group of three or more runs as before: one small exchange at startup, no probe and no warning. Then a connect probe: every rank RDMA-writes a token to every peer on every stripe and waits for its writes to complete and for every peer's token; a rank with no RDMA path to another (a ring of four without a switch, whose far ranks share no cable) fails this, and every rank keeps NCCL, with one warning naming the rank, rather than a kernel spinning at the first gather. Which HCA carries each peer's stripes follows the rule `fabric/tp`'s wire pairs by too, one copy for both (zig/src/cuda/roce_pair_rule.zig): a rank's k-th HCA on an IPv4 /24 pairs with the peer's k-th on it. On a switch, or two ranks on their cables, that is HCA h to HCA h, a stripe an HCA, as this path always paired them; on a switchless mesh with each cable on its own /24 (three GB10s, each port cabled to a different neighbour, `TF_ROCE_HCA` naming one function of each port) each peer gets the HCA on its cable, one stripe a peer. Every rank needs the same stripes to every peer and every listed HCA in use, and every rank's plan must hold; otherwise every rank keeps the same-numbered pairs, and a fabric those cannot connect keeps NCCL as above. `TF_ROCE_HCA` takes at most two names (`verbs.max_hcas`) and a longer list is refused by name; `NCCL_IB_HCA`, read when it is unset, is NCCL's own and this path keeps its first two. `fabric/tp`'s multirank wire, which a GLM rank borrows with `TF_GLM_ROCE_MULTI=1`, is the other route for per-pair ports. From then on `Group.allGather` sends a gather of up to the smallest rank's cap (512 KiB by default) this way and leaves larger ones to NCCL; the size alone decides, so every rank always takes the same path. A rank whose buffers are not 16-byte aligned gets `error.Misaligned` instead of falling back alone. Liveness is `tp_watch`'s, as for every group.

A failed exchange writes nothing into the gathered rows. Call `Group.check` after any synchronize whose result reads a gather: it returns the error the GPU or the proxy recorded.

`tf-cuda-test roce-gather <rank> [world]` runs on every rank (NCCL_COMM_ID set; world 2 by default): every size up to the cap and past it against NCCL's all-gather, byte for byte, a captured graph replayed, 3,000 mixed-size calls (16, 32 and 64 KiB a rank with tiny ones between) each against NCCL's rows, then each path's time a call at 4 to 64 KiB. Its last line, `RESULT roce-gather world N rank R: 32 KiB a rank RoCE X us a call (GO at most 25.0), 3000 mixed-size calls, M mismatch(es) (GO 0)`, is the gate a recipe reads before setting `TF_ROCE=1` at four ranks (the test needs it set there). Worlds 2 and 4 are measured (four GB10s behind a switch, 32 KiB a rank: RoCE 22.0 us a call against NCCL's 39.4, byte-equal, 0 mismatches in 3,000 calls); three ranks or more take the gather only with `TF_ROCE=1`, and any other value keeps NCCL.

### GLM TP2 post fusion

`TF_GLM_ROCE_FUSE=1` opts every GLM rank into fusing the FP32 rank-0-first sum and BF16 epilogue into an eligible two-rank RoCE gather. The default is off. The whole-window path takes fusion only at TP2, through `Group`'s fast RoCE route (not a local collective, NCCL, or the borrowed multirank route), inside the gather's byte cap, with 16-byte-aligned rows. Otherwise it runs the ordinary gather and standalone `hc_post` or `residual_add` kernel. Rank agreement refuses a mixed setting by name.

The TP2 fused launch adds the two FP32 shards once in rank order. Ordinary TP2 has one gather plus one post launch; fused has one gather carrying the same post arithmetic. At TP4 the current two-peer protocol adds all remote partials on a rank; an exact four-rank fusion must change that arithmetic and the number of peer waits, so this opt-in never takes it.

`tf-cuda-test glm-roce-fuse <rank>` runs the two-rank byte oracle for both epilogues at 1, 2, 4, 8 and 16 rows, with GLM's served width of 4096 and the real `x == xout` alias in both arms. It restores identical input bytes before the standalone reference. Three seeds make 30 fused/unfused cells a rank, including fused grids 1, 2, 4, 8 and the cap at 8. It covers signed zeros, subnormals, minimum and maximum finite magnitudes, infinities and NaNs, and compares every fused BF16 output byte with a real all-gather followed by the ordinary GLM post kernel. Run it on each of two ranks before enabling the switch. The HC oracle requires all four original input streams to be saved before the first in-place output store. The 16-row TP2 whole-window case saves one launch; a 16-row TP2 run through GLM's four whole-window sites saves four launches. No speed measurement is implied by those counts.
