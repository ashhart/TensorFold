# DeepSeek-V4.1 EXL3 on Metal, P4: an EXL3 pack admitted on the Metal lane, and how it was derived

P4 lets the DeepSeek-V4.1 Metal lane load and run an EXL3 pack. `weights.zig` takes the config's format and moves
the release's FP8 loader into `loadFp8` unchanged; `weights_exl3.zig` queues every trellis group through the same
`Loader`, `Place` and `fill`; `exl3_lane.zig` runs the linears through P1's one-row and row kernels, P2's gate/up and
P3's slot kernels; `moe_exl3.zig` is the decode MoE over them; `attn.zig`, `ctx.zig`, `forward.zig`, `prompt.zig` and
`prompt_layer.zig` choose the trellis or the FP8 projection per linear. No kernel and no arithmetic is new.

## Decisions

- Format: no flag. `Config.parse` already takes the format from `quantization_config.quant_method` (`exl3` or the
  release's `fp8`); the lane now dispatches on it. Tests: the shared format tests (an EXL3 config parses as `.exl3`,
  the release's as `.release_fp8`); the release fixture loads and runs through `loadFp8` in every existing layer,
  forward and serve test; an EXL3 group read as FP8 and an FP8 tensor read as a trellis are refused.
- Activations: a weight-format swap only. Every EXL3 linear reads the input the FP8 lane gives its FP8 weight: hq for
  wq_a and wkv, qrq for wq_b and the indexer's wq_b, act_quant of o per group for wo_a, act_quant of oa for wo_b, hq2
  for the shared and routed experts, sactq for the shared w2; the compressor reads hn, the indexer's wk latn, Engram
  its act_quant'ed rows, the head hfn (fp32 logits), as the release's bf16 weights do. CUDA's EXL3 lane feeds
  unquantized inputs, so the two backends may pick different tokens on the same pack.
- Launches carry at most 16 rows (prompts too, in pieces): the row kernels are bit-equal per row from 1 to 16, so a
  prompt row's bits equal its decode bits.
- An EXL3 layer keeps its trellises in `Layer.x3`; its FP8 fields stay empty (K = N = 0) and `projBatch` and the
  prompt's `proj` refuse such a field (`UnwiredExl3Projection`), so nothing falls back to an FP8 kernel silently.
- The pack's `wo_a` is one group per output group (`attn.wo_a.slice.G`), run one launch a group.
- DSpark's stages run FP8 kernels: an EXL3 pack with drafts on is refused at boot (`--no-drafts`).
- The real pack widens the release's bf16 Engram `q_weight` and `k_weight` to fp32; they load narrowed to bf16 only
  when every value's low 16 bits are zero (all 4 tensors on the real pack are), else `InexactNative`.
- Build: the package reaches the EXL3 kernels as `@import("core").exl3_projection` (core gets `metal` and
  `kernel_sources` in the package build; the engine module imports itself as `core`), since Zig refuses one file in
  two modules; P3's two files change only their import lines.

## Gates and results

- Host (`test-dsv41-metal-host`, M5 Ultra): every group of a tiny layer (mcg 2-bit, mul1 2.5-bit, 3INST 3-bit, mul1
  4-bit in turn) placed at the config's K x N with its width and codebook, markers checked after the fill;
  refusals: an FP8 tensor where a trellis is wanted (`UnsupportedProjection`), a trellis read as FP8
  (`UnsupportedProjection`), another K x N (`BadProjectionShape`), 4.5 bits (`UnsupportedExl3Width`), 2.5 bits on mcg
  (`BadMarker`), a 20-word tile (`BadTrellis`), a marker's value changed (`BadMarker`), a shard cut short
  (`BadSafetensors` at open). All pass.
- Device (`test-dsv41-metal`, M5 Ultra): one EXL3 layer (ratio-2 KV and index source) at 3 rows through
  `layer.encode`; on the GPU's own inputs, wq_a, wkv, wq_b, the indexer's wq_b and wk, the compressor's wkv and wgate
  (fp32), both wo_a groups, wo_b and the shared w2 are bit-equal to the serial chain (rotate_in, P1's row dot,
  rotate_out); the shared SwiGLU and its act_quant equal the serial chain (silu from `tf_dsv41_x3_silu`'s table,
  `actq32`); all 18 routed pairs' outputs equal `upPair` and `downPair` at their route weights. The rest of the suite
  (FP8 layers, forward, prompt, serve, vision) passes unchanged. Main's `early_test.zig` calls
  `Target.argmax`, which main's `target.zig` lacks, so the step does not compile on main; that import was dropped in
  the run copy only.
- Real pack (M5 Ultra, Mia-2.9, EAQ v1 2.9 bpw): all of it loads (189.8 GiB of trellises and natives, every group's
  shape, width and codebook checked); decode was not run: the lane needs packed Engram row shards
  (`tf-dsv41-engram-pack`, about 190 GB) and the shared M5 has 135 GiB free. A short greedy decode on a real pack is
  the remaining gate before the lane can be called served.
- Independence: `compare.py` over the changed files against the mlx-serve, mlx-stream and turboexl3 histories gives a
  longest normalized run of 1 line in every new P4 file but the host test (3) and an abstracted run of 1 to 3; main's
  `attn.zig`, `moe.zig` and `weights.zig` as the control give 1 (abstracted 1 to 7). `git blame` attributes every line
  P4 adds to its own commits.
