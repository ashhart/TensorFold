# Loaded groups in community-v2

A benchmark measures the group's serving endpoint. Rank count and machine count differ: several ranks can use one node. Managed and attached runs both read `GET /v1/benchmark/manifest` after the server loads. They copy its accepted inventory, never a client rank flag or `TF_NEMOTRON_WORLD` / `TF_BENCHMARK_RANK_COUNT` hint. Missing or invalid inventories stay unranked. Start followers separately and attach to the serving rank when measuring an existing group.

A new v2 receipt may add a root `group` object. The workload suite ID and digest stay unchanged; the topology is an additional comparison dimension, not a new prompt or token budget. V1 retains exactly its previous fields, canonical bytes and rank limit of 1, 2 or null. Legacy v2 receipts without `group` keep that same bound. New grouped v2 receipts accept 1 through 8 loaded ranks; a larger count without a complete group refuses.

```json
{"schema_version":1,"source":"loaded-group","rank_count":2,"category":"multi-node","nodes":[{"id":0,"ranks":[0],"hardware":{"cpu_model":"Example CPU","system_memory_bytes":137438953472,"memory_type":"unified","gpus":[{"name":"Example GPU","memory_bytes":128849018880,"cores":null}],"gpu_count":1,"source":"detected"}},{"id":1,"ranks":[1],"hardware":{"cpu_model":"Example CPU","system_memory_bytes":137438953472,"memory_type":"unified","gpus":[{"name":"Example GPU","memory_bytes":128849018880,"cores":null}],"gpu_count":1,"source":"detected"}}]}
```

The manifest carries the same `group`; `settings.rank_count` in its receipt must equal `group.rank_count`. Node IDs are ordered ordinals. Their sorted rank lists cover every rank from zero through count minus one exactly once. Each node carries its public CPU model, system memory, memory type and GPUs, with the same allowlist as ordinary receipt hardware. GPUs describe devices used by the loaded group, deduplicated within a node. Root `hardware` repeats the node containing serving rank zero for older displays; it must not be mistaken for the whole group.

CUDA groups query the loaded communicator's count and rank, collect each rank's inventory at startup, and publish only the frozen result. Private boot and GPU identities establish node membership and device deduplication but never enter JSON. Paired Metal transports exchange that inventory during their existing startup handshake. An older paired peer can still serve, but its missing inventory leaves the pair unranked. A missing identity, conflicting hardware, unsupported count or incomplete rank cover cannot become a one-rank fallback. HTTP reads copy the snapshot under the unload lock; a parked or draining engine attests no loaded group. Ordinary single-rank engines retain their local hardware probe. ROCm distributed inventory is not yet implemented and remains unranked; ROCm publication is also still disabled.

The receiver should partition on `suite.id`, `suite.sha256` and `group.category`, keeping legacy receipts without a group separate. Within a category, retain `group.rank_count`, `group.nodes[].ranks` and each `group.nodes[].hardware` as comparison filters. `group.category` is `single-node` exactly when `group.nodes.length` is one, otherwise `multi-node`. Do not infer it from rank count or GPU count. In particular, two GPUs on one node belong to `single-node`, while two nodes sharing identical GPU names remain `multi-node`.

The loaded-group source is provenance within the engine, not cryptographic authentication. A saved receipt or an arbitrary attached server can still lie. Validation detects structural inconsistencies such as a changed settings count or duplicate ranks; it cannot authenticate hardware supplied by an untrusted server. Transport and link class, per-rank timing, effective settings, boot agreement, exactness at that world size and process start order still belong in the local run report. A failed launch is not a slow successful measurement.

Community-v2 publication remains disabled until the receiver accepts its routing and topology fields and separates those categories. This engine change does not implement or certify the receiver's ranking. Runs above eight ranks, missing inventories and unsupported transports stay in local reports.
