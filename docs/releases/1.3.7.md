# TensorFold 1.3.7

Released 27 November 2026. Tag `v1.3.7` (commit `b336654937`), cut from main at `cd1a825e9e`. Previous release: 1.3.6 (`v1.3.6`, `f56b1420ff`); the range holds 355 commits.

Upgrade from 1.3.6 for the Metal library-load fixes: libraries that the macOS 27.0 Metal compiler refused load again, including Inkling 2 Mini's runtime library and rewritten Flash Next libraries. Default output is unchanged everywhere it was read (see [Checks](#checks-that-ran)).

## Fixed

- **Metal library loading (#5376, #5405, #5303).** Source rewriters no longer add a second threadgroup-size attribute to a kernel. The M5 compiler refused the whole library when a kernel declared it twice, so Flash Next's SSD 4-bit group-32 prompt path and Inkling 2 Mini's runtime convolution library (broken since #4593) failed to load. Inkling 2 and LFM2 generated libraries now also refuse repeated or conflicting reservations while assembling.
- **CUDA programmatic dependent launches (#5381).** A host check rejects any enumerated dependent launch of a kernel that does not wait for its dependency first. DeepSeek's generic x3ld kernels now wait first.
- **Flash Next on CUDA.** `TF_FLASHNEXT_PREFILL_MTP_LEAN=1` no longer fails prompts over about 1,400 tokens (#5358, fixes #5332). A greedy draft beside another open stream uses the same `TF_FLASHNEXT_CONFIDENCE` stop rule as a lone stream (#5265). TP=2 decode stages graph inputs before every capture and replay, and frees the graph before aborting NCCL (#5222, fixes #2974). Expert residency caps follow the selected GPU instead of device 0 (#5221, fixes #4952).
- **Checkpoint and pack validation (#5306).** A sharded checkpoint whose index disagrees with its shard headers is refused at load. Saved prompt state is keyed to the TFQ3 tables the loaders already check. No extra weight bytes are read.
- **Inkling 2 Mini draft memory (#4622).** Window fitting prices each drafted token at its own size, so a 64 GB limit holds the full draft window for eight streams.
- **GLM-5.3-Flash.** TFQ3 row signs on Metal come from each tensor's absolute row, and fused runs keep their recorded boundaries on every prompt path (#5225). On CUDA, layer read-ahead uses the checkpoint's model prefix, which fixes full GLM/DSA checkpoints (#5264).
- **Desktop development builds (#4545).** macOS ARM64 development builds stage engine 1.2.8 instead of 1.1.0, so tool calls reach Desktop as structured calls.

## Improved

Measured on the hardware named; tokens unchanged in each case.

- **Inkling 2 Mini, M5 Ultra:** the register-tiled dense BF16 kernel fills a 2K-token prompt 5.7-7.3% faster (#5201). In the release reads, prompts were 23% faster and decode 3-6% faster than 1.3.6.
- **Inkling 2 Mini, M3 Ultra:** 3:1 GQA decode and verification read each K/V head once for its three query heads; four-stream decode is 12-14% faster (#5206). K and V short convolutions share one dispatch, about 1-2% faster decode (#5004). Vectorized router and gate passes are about 1% faster on M3 and M5 Ultra (#5207).
- **Idol background removal, Metal:** native FP32 BiRefNet takes 0.172 s against the SDK's 0.48-0.52 s (#5020).
- **Prompt-cache pressure is reported (#5312).** When memory pressure stops the cache keeping new states, request logs say so, and `/memory` adds `prompt_cache_keeping_new_states` and `prompt_cache_hold_reason`. What the cache keeps or sheds is unchanged.

## Added

All new switches are off by default; leaving them unset serves exactly as 1.3.6 did.

- `serve --confidential` (#5180): refuses at startup every flag and variable that keeps or sends request content, and turns core dumps off.
- `serve --execution-witness` (#5184): attests the Qwen3.8-27B-class Metal engine for the 9B and 27B MLX 4-bit checkpoints by hashing the Metal libraries built at load.
- `serve --listen-fd N` (#5183): serves on a Unix socket handed over by the parent process, taken once before the model loads.
- `TF_CUDA_SCHED=auto|spin|yield|blocking` (#5253): how a CUDA model's host thread waits for its GPU.
- `TF_Q35_DFLASH_TRACE=PATH`: one JSONL record per Qwen3.5-family CUDA DFlash round, for `tools/dflash_replay.py`.
- `TF_NEMOTRON_METAL_KV_PAGES=1`: on pre-M5 Metal, drafted verification computes attention one row at a time, so drafted output stays byte-identical to plain (#5267).
- Inkling 2 Mini: `--drafter` accepts a DFlash 2 drafter (#4917); opt-in GPU token sampling (#5153); an opt-in draft-only 4-bit/64 head for DSpark drafting (#4253).
- GLM-5.3-Flash on one Mac: an MTP load without a stored draft head can build an in-memory 4-bit/64 draft head from an 8-bit/64 LM head when memory allows. Target verification keeps the original head (#5165).
- Models and platforms: Hy4-flash CUDA FP8 Engram kernels (#5087, #5099); CUDA GPTQ int4 W4A16 for group-128 experts and the LM head (#4183); DeepSeek-V4.1 EXL3 routed experts on Metal (#5063); Kolibri 1.1 on CUDA up to 2,048 tokens (#4941); Thor (sm_110) code in the Linux CUDA archives (#5053); `tf-idol-generate` takes PNG, JPEG and WebP input (#1787).

## How the changed behavior works

- **Absolute TFQ3 row signs.** A TFQ3 weight's inverse-FWHT signs are indexed by the row's position in its tensor. Metal used to restart that index every 8,192 rows for large tensors, and at fixed sizes for fused runs. 1.3.7 uses the absolute row for standalone tensors and the recorded member boundaries for fused runs, which matches the format and the CUDA loader.
- **Draft-window memory.** Inkling 2 Mini sizes its draft window from each drafted token's actual bytes rather than a flat per-token price, so more of the window fits a given memory limit.
- **Confidential mode.** `--confidential` checks the parsed command line and environment once at startup and refuses to start if anything would persist or forward request content. It does not change replies.

## Upgrade notes

- **Homebrew:** `brew upgrade tensorfold`. The archives are signed; `tensorfold-native --version` prints 1.3.7.
- **No migrations or configuration changes are needed.** Defaults are unchanged and every new switch is opt-in.
- **Old Flash Next packs:** a pack made before 1.0 without a recorded source is now refused, with the command that rebuilds it printed in the error. Rebuild it once.
- **Mismatched sharded checkpoints** are refused instead of loading. Re-download the checkpoint if you see this error.
- **Linux CUDA archives** carry code for sm_80, sm_86, sm_110, sm_120 and sm_121. 1.3.6 carried sm_89 instead of sm_110.

## Checks that ran

- **CI:** every GitHub job passed on the release's source commit `cd1a825e9e` (zig, zig-b, zig-windows, macos-dev-tools, pytest, format).
- **Release reads:** twelve served comparisons of the release tip against 1.3.6, all with identical tokens.
  - Apple M5 Ultra (Metal): Qwen3.8-27B plain and with DFlash 2, Flash Next, and Inkling 2 Mini.
  - NVIDIA GB10 (CUDA): Qwen3.8-27B plain, with DFlash 2 and in NVFP4; Flash Next NVFP4 on two boxes; and Nemotron 3.5 Lightning.
  - Two GB10s at TP=2: GLM-5.3-Flash NVFP4, within 0.7% at one and two streams, with no unequal streams.
  - AMD Strix Halo (HIP): Qwen3.8-27B.
- **Build and signing:** all 165 CUDA fatbins were rebuilt with the release's architecture list and matched their checksums. The macOS arm64, Linux aarch64 and Linux x86_64 archives were signed, and a fresh download verified.

## Not verified, and known issues

- **Metal was read on an M5 Ultra only.** M1-M4 and M3 Ultra were not read for this release.
- **GLM-5.3-Flash-TFQ3 on Metal was not in the release reads**; the GLM read was NVFP4 on CUDA. After release, #5456 reports corrupted replies with 1.3.7 on an M5 Ultra for the published checkpoint, where 1.3.5 is correct. The 1.3.6 source does not contain the row-sign change above. A local TFQ3 copy whose LM head is not a TFQ3 record served correctly on both 1.3.6 and 1.3.7, so it does not settle the report. Until it is resolved, use 1.3.6 or 1.3.5 for that checkpoint on Metal.
- **Known slowdown:** on a GB10, Qwen3.8-27B with its DFlash 2 drafter is about 2-2.5% slower at four greedy streams than 1.3.6. Batches whose streams use different draft widths split their draft-head work by width (#4439). Tokens are unchanged; one stream and sampled runs are unaffected. The release page blamed CUDA graphs for this; that was wrong, because DFlash graphs are off by default in both versions.
- **Nemotron at four streams on a GB10** read 3.3% slower in one greedy chat cell. A comparison with the suspected change reverted moved that cell 4.7% in the other direction, so the cell is noise-prone and the result is unsettled.
- **Not read for this release:** sm_80, sm_86, sm_89 and sm_110 GPUs, Windows, and XPU.
