CUDA operators for the framework-free backend use raw device pointers and a caller-owned stream.

`movement.cu` provides disjoint byte copies, contiguous row gathers with int64 indices, and three-axis strided materialization where the innermost axis is contiguous. A copy-span table has three 64-bit words per entry: source address, destination address, byte count. All source and destination allocations and descriptor tables must remain live until the stream finishes; destination spans must not overlap. A caller supplies a zeroed device uint32 error flag for gathers; invalid indices set it and leave the corresponding output row untouched. The round must refuse commit when this flag is nonzero.

`pointwise.cu` expands BF16 to FP32, rounds FP32 to BF16 with round-to-nearest-even, and adds two BF16 tap rows in FP32 before rounding once to BF16. It preserves separate Torch-operation rounding points and does not use reduced-precision accumulation. NaN payloads, signed zero and subnormal behavior require the raw-byte GPU gate before qualification.

The exported `*_kernel` names are stable C symbols for fatbin loading. C launcher functions exist for development parity checks only; the Zig runtime loads device images through the driver API. Compile without fast math, with `--fmad=false --ftz=false`.

These operators have not passed GPU qualification. `tools/zig/check_torch_ops.py` tests actual checkpoint-config dimensions, accepted-path gathers, padded views, KV slices, multi-tensor copies and raw floating-point encodings against Torch. The next gate uses real-weight captured intermediate values before any model or end-to-end parity claim. Views, reshape, transpose and unbind that do not materialize storage belong in the native tensor descriptor rather than in a kernel.

`indexing.cu` widens signed int32 plans to int64, selects a middle axis from contiguous storage, gathers per-row columns, and maps draft-vocabulary indices to token IDs without changing bytes. Index errors use the same caller-owned uint32 error flag. `grammar_mask.cu` reads little-endian packed vocabulary bits and writes negative infinity only at disallowed BF16 or FP32 logits, leaving unconstrained rows untouched; the host must provide unique target rows. FP16 is not an accepted grammar dtype. All these candidates remain unqualified until their raw-byte GPU cells pass.

`nucleus.cu` keeps the target sampler's FP64 CPU-scalar reciprocal multiplication, subtraction, exponential, multiplication by 2^40, floor and int64 conversion at their original rounding points. It supplies an exact integer row sum using unsigned two's-complement words; valid vocabulary sizes keep fixed-point mass totals below signed-int64 overflow. It does not implement or replace the topk candidate selector, maximum selection, rational nucleus cutoff or keyed host draw. Libdevice/ATen transcendental parity remains a GPU gate.

`logprob.cu` supplies gathered BF16/FP32 logits minus the existing FP32 logsumexp, and the owned deterministic int64 alternative-token key. It normalizes both signed zeros before ranking, keeps the vocabulary ID tie break, and does not replace the already-owned logsumexp kernels or the selector.

`argmax.cu` ranks raw BF16/FP32 encodings, treats both zeros as equal, and chooses the first NaN or first maximum. Its shared comparator has passing CPU contracts and a reversed-tie failing mutant; CUDA qualification is separate. `norm_rotary.cu` tests two explicit accumulation candidates for aligned BF165120 RMS, with the active packet and reduction schedule, and full-precision phase/cos/sin. Only a variant whose complete native byte gate passes may be selected; the manual FP32-square/mean drafter norm remains separate work.

`topk.cu` is an unqualified F32 unsorted selector using four histogram passes and ordered compaction. It retains selected source bits and local indices, including signed-zero and NaN threshold classes, with caller-owned scratch. Its result order must match the deployed ATen path, not merely a sorted multiset. FP64 sorted selection remains held pending the exact deployed selection/sort contracts.

Nemotron's CUDA serving norms, routing, Mamba gates and attention are already owned Triton or CUDA code. Its greedy draw stores int32 IDs, so `tf_argmax_rows_i32_kernel` uses the same tested comparator as the int64 form and writes that type directly. `tf_narrow_indices_kernel` provides Torch's low-word int64-to-int32 conversion for plans and sampled IDs. `tools/zig/check_nemotron_ops.py` books the serving shapes, aliasing adds, grammar-bias signs, copies, gathers and casts under the engine container's compiler flags. Nemotron's top_k=0 sampler sorts FP64 probabilities and scans them; the 27B fixed-point mass kernel is not a substitute.

`nemotron_sampler_core.cu` preserves Nemotron's distinct FP64 nucleus pointwise stages: device-scalar division, ranked relative exponentials, division of captured floating scans by their totals, wrapping keyed-uniform generation and masked Gumbel scores. Its inputs include the stable ordering, floating cumulative sums and row totals from the reference; those operators are not claimed to be replaced. No fixed-point mass or CPU-scalar reciprocal substitution is used.

`cast_f64.cu` widens native BF16 or FP32 logits into the sampler's FP64 storage. `argmax_f64.cu` orders raw IEEE64 scores and selects the first maximum or first NaN without reducing their precision. Their byte gates include vocabulary-size rows, strides, ties, signed zero, subnormals and NaNs. Stable FP64 sorting and floating scan/sum are still separate deployment gates.

`nemotron_limits.cu` counts the original FP64 comparisons into int64 nucleus/min-p cutoffs and gathers a selected FP64 probability divided by its captured FP64 total, rounded once into FP32 confidence. The floating cumulative sum and total must come from qualified operators; integer counting does not change their precision or rounding.
